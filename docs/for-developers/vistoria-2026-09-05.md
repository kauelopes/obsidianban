## 1. O que o projeto é (estado real)

**ObsidianKan** = servidor MCP (Node 22, TS, `node:http` cru, better-sqlite3) que transforma um vault Obsidian num Kanban operado simultaneamente por humanos e agentes de IA.

- **Fonte de verdade**: `.md` em `<vault>/kanban-data/<project>/`; SQLite é índice derivado (reconcile no boot por sha256, watcher chokidar com debounce 500 ms e reversão de campos imutáveis, escrita atômica tmp→fsync→rename, audit NDJSON append-only).
- **66 tools MCP** (`server/tool-catalog.ts`), 3 papéis: manager (66), pm (50), dev (13). Transportes: Streamable HTTP `/mcp`, REST `/mcp/tool/:name` (idempotência por `request_id`), stdio.
- **Web SPA** (React 18 + Vite 6, ~13,5k linhas): Dashboard `/`, Projetos, workspace `/board/:project` com 4 abas (board, arquivos, estatísticas, metas), card detail, wizards de projeto (KAD) e de sprint, Horizonte (metas/calendário), Estatísticas `/atividade` (4 sub-abas), Configs (tema, editor de skills, ajuda). Sessão de manager injetada em loopback; TokenGate na LAN.
- **Workflow autônomo de sprint** (`scripts/sprint-workflow.ts`, processo Node separado): loop até 50 rodadas; triagem da coluna review (determinística + LLM via `toolRunner` com pm-token); dev = `claude` CLI headless com dev-token via `dev.mcp.json`, 3 cards por spawn, timeout 45 min; sweep de órfãos no `finally`.
- **Jobs de longa duração** (`JobManager`/`JobStore`): processo detached por card, log em disco, watchdog de stall (20 min) e backstop 12 h, reidratação no boot, hand-back condicional do card.
- **Hooks de sprint + git**: branch `sprint/<id>` no start, `add -A` + commit + merge `--no-ff` em `main` no close.
- **Métricas**: `token_log` (medido) + `terminal_usage` (estimado, ingestão de `~/.claude/projects/**/*.jsonl`), `/flow`, `/digest`, `/activity`, custo por role.
- **Ops**: `make server-*` com `.env`; sem systemd/cron, sem CI, sem lint, sem Docker.

Pontos fortes verificados: zero `console.log`/`any`/`@ts-ignore` em `src/`; imports `.js` corretos; comentários explicam o "porquê"; 10,6k linhas de teste no server + 35 arquivos no web com fixtures de contrato capturadas do servidor real; escritas atômicas replicadas com disciplina; `tool-catalog.md` gerado e 100 % sincronizado.

## 3. Achados de robustez e qualidade

**Server**
- `sprint-workflow.ts`: `MODEL='claude-opus-4-8'` hardcoded (:72) + tabela `PRICE` própria — 3ª fonte de preço (com `shared` e `terminal-usage`); `Number(env)` sem guarda em `SPRINT_MAX_ROUNDS`/`RATE_LIMIT_*` → `NaN` encerra a sprint no round 1 em silêncio; rate-limit bloqueante até 50 min; sweep de órfãos 4 HTTP sequenciais por card.
- Fase do workflow derivada por parsing de emoji (`▶`/`◀`) nos últimos 64 KB do log (`workflow-runner.ts:330-408`) — contrato implícito sem teste.
- `planning/` e `sprint-planning/`: 6 pares de arquivos homônimos, ~50 % duplicado; `inFlight` em memória (restart deixa sessão presa em `generating`); `ClaudeRunner` guarda um único `child` → `cancel()` mata o turno errado.
- `index.ts` (404 l.) com lógica de negócio inline (auto-launch/auto-close, 3 handlers) e `throw new Error('forbidden')` (:220) → 500 em vez de 403.
- Leituras O(n): audit NDJSON varrido inteiro em `/flow` e `/digest` (teto 200k); `JobStore.list()` relê todos os JSONs em cada `GET /workflow/agents` (polling de 3 s).
- Constantes fora de `constants.ts` em 14 arquivos; `DAY_MS` triplicado; ~25 scripts `smoke-batch*` mortos em `scripts/`; comentários obsoletos "Task 5" em `supervision.ts`; `listEscalations` não recebeu o fix SQL aplicado a `listStalledReviews`.
- Sem testes: `workflow-readiness`, `guards`, `skills`, `audit-scan`, RBAC negativo.

**Web**
- `useBoard` chamado 3× em `App.tsx` (:29, :54, :99) → `list_projects` + N×`list_sprints` + `list_cards` a cada troca entre `/`, `/projetos`, `/card/:id`.
- `Metrics.tsx` 842 l. (4 abas num arquivo), `detail.css` 2117 l. sem escopo.
- Vite proxy cobre só `/mcp|/events|/health|/metrics` → Dashboard, Home, Files, AgentsStatusBar, Revisão e Skills quebram em `vite dev`.
- `window.confirm` em `SkillsPanel.tsx:81` (existe `ui/Dialog.tsx`); 2 `<h1>` em `Configs.tsx`; `CardDetail.tsx` (479 l.) sem teste dedicado; `api/events.ts` (SSE) sem teste.
- `package-lock.json` rastreado apesar do `.gitignore`; `shared` sem script `test`; `shared/README.md` descreve 17 tipos/14 eventos (reais: 30+/28).

**Working tree atual** = 3 frentes misturadas: (a) aba Configs + editor de skills (sem testes), (b) métricas board vs terminal (completa, com testes), (c) 4 bugfixes reais sem teste de regressão (`supervision.ts` filtro SQL, `Horizon.tsx` 403 vs offline, `Files.tsx` troca de projeto, `metrics.ts:265` vazamento de terminal no recorte por card).

## 5. Propostas — roadmap priorizado

### P0 — Segurança e fechamento do branch (1–2 dias)

1. **RBAC no serviço** (C1): `requirePmOrManager` em `create`/`bulkCreate`/`delete`/`setArchived` (`card-writer.ts`) e `reorder` (`card-mover.ts`); `index.ts:220` passa a usar `requireManager`. Teste gerado a partir de `TOOL_CATALOG`: para cada tool com `access !== 'all'`, chamar com dev-token → 403 (`tests/service/rbac.test.ts`).
2. **Editor de skills** (C5): `PUT /skills/doc` só para `SKILL.md` e `reference/*.md`; `.sh`/`.json` somente leitura (ou validação por schema JSON). Testes em `tests/service/skills.test.ts` + `http.test.ts`. Decidir fonte: manter `<repo>/.claude/skills` ou mover para `<vault>/.kanban/skills/` (já existe `OBSIDIANKAN_SKILLS_SOURCE`) — recomendo o vault, para o servidor não editar o próprio source tree.
3. **workflow-readiness** (C3): checar `repoExists` antes de emitir tokens; garantir `.claude/settings.local.json` no `.gitignore` do repo-alvo; testes.
4. **Rotas GET** (C6): helper único `requireLocalOrToken(req)`; quando `HOST` ≠ loopback, exigir Bearer (o SPA na LAN já tem token pela TokenGate). Remove as 8 cópias.
5. **Branch atual**: dividir em 3 commits (Configs/skills, métricas, bugfixes); testes de regressão para os 4 fixes; aplicar o filtro SQL também em `listEscalations`; remover `package-lock.json`.

### P1 — Robustez operacional (3–5 dias)

6. **`WorkflowStore` persistente** (C4), espelhando `JobStore`: `.kanban/workflow/<sprint>.json` com pid/log/started_at; `init()` no boot readota processo vivo ou marca `lost`; opção `WORKFLOW_RESUME_ON_BOOT=true` relança sprint `active`. Elimina o procedimento manual pós-reboot do CLAUDE.md.
7. **Fail loud**: `/health` expõe `workflow: {enabled, script_found, tokens_ok, claude_cli_found}`; boot com `WORKFLOW_ENABLED=true` e pré-condições faltando vira erro, não `logger.warn`. Dashboard mostra o estado.
8. **Contrato estruturado workflow → server**: o script emite `POST /workflow/heartbeat` (pm-token) com `{round, phase, card_id, tool}` em vez de emoji no log; `derivePhase` some. Testado dos dois lados.
9. **Git isolado por sprint** (C2): hook cria `git worktree add .worktrees/sprint-<id> sprint/<id>`; o dev agent roda com `cwd` no worktree; o close faz merge a partir do worktree e o remove. Resolve a corrida com o working tree do humano e abre caminho para devs paralelos. `MAIN_BRANCH` via `git symbolic-ref refs/remotes/origin/HEAD` com fallback configurável. `add -A` → `add -A -- ':!.claude/settings.local.json'` ou só arquivos rastreados.
10. **`sprint-workflow.ts` endurecido**: `readIntEnv(name, default)` com validação (padrão de `devRoundTimeoutMs`); `WORKFLOW_DEV_MODEL`/`WORKFLOW_TRIAGE_MODEL` em env; uma única tabela de preços em `shared` (`MODEL_PRICES_USD_PER_TOKEN`) consumida por script, `terminal-usage` e web; rate-limit com backoff exponencial e teto por rodada em vez de 10×300 s.
11. **Autostart**: `make install-service` gera unit systemd `--user` (`Restart=on-failure`, `EnvironmentFile=.env`).

### P2 — Arquitetura e organização (1–2 semanas, incremental)

12. **Motor de wizard único**: `wizard/` com `WizardEngine<TSteps>`, `SessionStore<T>` genérico, `ClaudeRunner` com `Map<sessionId, child>`; `planning/` e `sprint-planning/` viram definições de etapas + materializadores. `inFlight` persistido na sessão com timestamp para destravar no boot.
13. **`index.ts` só wiring**: auto-launch/auto-close → `services/sprint-orchestration.ts`; handlers inline → serviços; `http.ts` com tabela de rotas `[method, pattern, auth, handler]`.
14. **Higiene**: constantes para `constants.ts` (14 arquivos), `DAY_MS` único, apagar `scripts/smoke-batch*` (ou mover para `docs/archive`), atualizar comentários "Task 5".
15. **Leitura escalável**: tabela `audit_index` no SQLite alimentada no `appendFile` (op, ts, card, project) para `/flow`/`/digest`; `JobStore` com cache em memória invalidado em `save`.
16. **Web**: `BoardProvider` no topo do router (mata o N+1); `Metrics.tsx` em 4 arquivos; `detail.css` dividido por feature (`card.css`, `metrics.css`, `configs.css`); proxy Vite `^/(mcp|events|health|metrics|activity|flow|digest|vault|workflow|skills)`; `Dialog` em vez de `window.confirm`; hierarquia de headings; teste de `CardDetail` e de `events.ts`.
17. **DX/CI**: ESLint (typescript-eslint + react-hooks) + Prettier; GitHub Actions `typecheck + test + build:web`; script `test` em `shared` (mover testes de `parseSections`); `Dockerfile` opcional.

### P3 — Novas funcionalidades (ordem sugerida por valor/custo)

18. **Notificações de saída (webhook/ntfy/Telegram)**: assinante do `SSEEventBus` que faz POST para `NOTIFY_WEBHOOK_URL` nos eventos que exigem humano (card → review, escalação, sprint drenada, `SPRINT_GIT_MERGE_CONFLICT`, `JOB_STALLED`, workflow abortado). Hoje só quem está com o browser aberto sabe. Baixo custo, alto valor para supervisão assíncrona.
19. **Pergunta estruturada ao humano**: tool `kanban_ask_human(card_id, question, options?)` — o card entra em review com bloco `## Pergunta` no `.md`; o Dashboard mostra formulário; a resposta é gravada em Notes e o card volta para `todo`. Substitui o protocolo implícito "review = precisa de humano" por algo que o agente pode consultar (`kanban_get_card` devolve a resposta).
20. **Teto de custo por sprint** (`budget_usd` no sprint, `kanban_create_sprint`): o workflow lê `/metrics` por sprint a cada rodada e para graciosamente com escalação ao atingir 90 %/100 %. Métricas já existem; falta só o guard.
21. **Retrospectiva automática no close**: hook que gera `<project>/sprints/<id>-retro.md` no vault (cards feitos/devolvidos, custo por card, bloqueios, tempos de fluxo do `/flow`, commits do `git-activity`). Nasce como nota Obsidian, linkável.
22. **Coluna visual `blocked`** (decisão pendente do task-defer): cards com `blocked_by` não satisfeito aparecem em coluna/faixa própria no board e no `pick_next` explicam por que não são elegíveis.
23. **Definition of done executável**: campo `verify_command` no card; ao mover para `done`, o servidor roda o comando como job e só aceita a transição se sair 0 (senão devolve para `in_progress` com log). Usa o `JobManager` existente.
24. **Devs paralelos por sprint**: com worktrees (item 9), `DEV_PARALLELISM=N` spawna N harnesses, cada um com `pick_next` próprio; `JOB_MAX_CONCURRENT` já existe como precedente.
25. **Harness plugável** (`DEV_HARNESS=claude|codex`): o estudo `codex-headless-study.md` já mapeou; abstrair `runClaudeDev` numa interface `DevHarness { spawn, parseUsage }`.
26. **Card ↔ código**: card guarda `branch`, `commits[]`, `pr_url`; `git-activity` já lê commits; card detail mostra diffstat e link do PR.
